4 · How we test visually before the UI Menu exists

The correction: UI Menu is last only as navigation + production bootstrapper. Visual testing does NOT wait for it. Session 1 builds a playtest rig right after the Vehicle Physics lands (bridge 3 in the timeline) — a minimal dev scene that composes kernel + driver + input + content (one track, one car) + camera + placeholder HUD. Each visual epic plugs into the rig as soon as it ships and is verified by screenshot/playtest. The UI Menu replaces the rig at the end.
Per-component · immediate

Screenshot isolation

Each visual piece (camera view, HUD panel, VFX streak, audio profile) is validated in a dedicated test scene via screenshot-isolated / screenshot-camera — no full app required. Already the established pattern.

Integrated · after VP

Playtest rig (dev)

Minimal dev scene that runs a real race loop (sim + car + track + camera). Each S2 visual epic is plugged in & verified in real motion with screenshot-game-view and lean playtest passes.

Formal · near the end

CD-PLAYTEST (MVP gate)

Milestone requires: cockpit camera + engine sound + art-in-motion playtest. Runs on the composed app once UI Menu lands — the final visual sign-off.
