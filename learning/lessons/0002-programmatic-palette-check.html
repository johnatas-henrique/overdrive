Overdrive Asset Production · Lesson 2

Programmatic palette checks: measuring an image before judging it

2026-08-06 · Mission: MISSION.md · ~25 min

What this lesson adds

Lesson 1 taught the visual checklist. This lesson adds a small machine-checkable layer: image dimensions, approximate corner background, and dominant colors. The script does not decide whether an image is beautiful or anime. It catches measurable deviations before they consume your attention.

Important: a program can say that an image contains a gray background and the expected red. It cannot prove that the silhouette, drawing quality, or emotional tone belongs to Overdrive. Visual judgment and measurement work together.

The first concept: a color is data

A color can be represented as three numbers: red, green, and blue. `#CCCCCC` means red 204, green 204, blue 204. The art bible's gray presentation background is therefore a measurable target, not only an impression of gray.

RepresentationExampleMeaning
Hex#E03C31Compact notation used in the art bible
RGB(224, 60, 49)Three channels from 0 to 255
Distancesqrt((R₁-R₂)² + ...)Approximate difference between two colors

What the script does

  1. Opens each PNG with Pillow.
  2. Reports width, height, and color mode.
  3. Samples small patches from the four corners.
  4. Calculates their average color and compares it with `#CCCCCC`.
  5. Reduces the image to a small sample and reports its dominant colors.

The script is at learning/reference/check-image-palette.py. It is deliberately small enough to read from top to bottom. The useful idea is not memorizing Python; it is learning how a visual requirement becomes a test.

Run it

The WSL Python in this environment has no Pillow, so the lesson uses the embedded Python shipped with your ComfyUI installation. In PowerShell:

& "E:\ComfyUI\ComfyUI-Easy-Install\python_embeded\python.exe" `
  "D:\projects\overdrive\learning\reference\check-image-palette.py" `
  "D:\projects\overdrive\design\art\reference\generated\team_tier1_a\front-d-1.png" `
  "D:\projects\overdrive\design\art\reference\generated\team_tier1_a\side-1.png" `
  --output "D:\projects\overdrive\learning\reference\lesson-2-palette-results.json"

The same command can inspect a whole directory after the script is extended with directory input. We start with two images because small feedback loops are easier to understand.

How to read the result

FieldQuestion it answersWhat it cannot answer
sizeIs the image the expected resolution?Whether the composition is good
corner_averageDo the corners resemble the required gray background?Whether the whole background is clean
background_distanceHow far is the sampled gray from #CCCCCC?Whether the image contains a correct livery
dominant_colorsWhich colors occupy much of the image?Whether each color is assigned to the right car part

The threshold in this first script is `25` RGB-distance units. It is a teaching threshold, not a final production rule. A future asset-pipeline specification should choose thresholds from real samples and record them.

Evidence from the actual Overdrive images

We ran the script against the current project references front-d-1.png and side-1.png. Both images look like gray-background car presentation sheets, but the corner averages were darker than the literal target #CCCCCC:

ImageCorner averageDistance from #CCCCCCStrict threshold result
front-d-1.png#AFACAE52.58Outside 25
side-1.png#B9B7B834.67Outside 25

This is not evidence that the images are unusable. It is evidence that the test is too simplistic for a final gate: the corner samples include presentation shading and the target may have been interpreted as a gray range rather than one exact pixel color. A useful verifier reports the discrepancy; a human or a better segmentation rule decides whether it matters.

What the check can reveal in Overdrive

  • A supposedly neutral presentation image whose corners are blue, green, or warm orange.
  • A team image whose dominant red is too dark or too brown compared with the team palette.
  • An image with an unintended background or scene color occupying most of the frame.
  • Images whose dimensions do not match the intended reference or multiview workflow.

It will not detect the invented word on a tire. That remains a visual/OCR problem. It will not decide whether the Porsche's silhouette belongs in a scene. That remains an art-direction and context decision.

Exercise

  1. Run the script on front-d-1.png and side-1.png.
  2. Find the two corner_average values.
  3. Compare the reported dominant colors with the intended white, red, black, and gray presentation background.
  4. Write one sentence distinguishing what the script proved from what still requires visual inspection.
Expected reasoning

The script can provide evidence about dimensions, corner color, distance from #CCCCCC, and dominant colors. It cannot prove that the car has the right silhouette, that the red is placed on the correct body panels, or that the rendering feels like Overdrive. Those require the visual checklist.

Key lesson: measurement does not replace judgment. It exposes assumptions. Here, the script exposed the difference between “the prompt requested #CCCCCC” and “the rendered background is exactly #CCCCCC.”
