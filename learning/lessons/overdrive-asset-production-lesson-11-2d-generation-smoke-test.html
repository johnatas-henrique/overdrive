Overdrive Asset Production · Lesson 11

Executable Krea2 2D smoke test

2026-08-10 · Mission: MISSION.md · ~60 min

The purpose of this lesson

This lesson does not ask you to search for a model or continue an experimental graph by trial and error. It provides a fixed manual graph specification and a test procedure that proves whether the baseline is technically valid and visually useful.

Do not send an unapproved image into 3D. First prove that the 2D pipeline is reproducible and obeys the design brief.

2. Build the baseline graph manually

No workflow file is required. Create the following nodes in ComfyUI and connect them exactly as shown. This keeps the lesson reproducible without depending on a local workflow export.

Use the native model-only LoRA loader and keep the Enhancer available as a disabled, separately testable branch.

Its graph contract is:

UNETLoader → LoraLoaderModelOnly → Krea2T Enhancer (disabled) → KSampler → VAEDecode → SaveImage
CLIPLoader ───────────────────────────────→ CLIPTextEncode → KSampler
VAELoader ───────────────────────────────────────────────→ VAEDecode
EmptySD3LatentImage ────────────────────────────────────→ KSampler
ConditioningZeroOut ────────────────────────────────────→ KSampler negative

Important: Krea2 Turbo uses ConditioningZeroOut rather than a text negative prompt. The positive prompt contains all visual restrictions. Variant A intentionally starts without the LoRA trigger; variants B, D, and E add anime style. The Enhancer is disabled in A–D and enabled only in E.

3. Before running anything

  1. Open ComfyUI.
  2. Create the graph from the node contract in Section 2.
  3. Confirm that every model selector resolves without a red or missing-model warning.
  4. Confirm that LoraLoaderModelOnly resolves the animeEnhance LoRA and that ComfyUI-Krea2T-Enhancer is available for the optional Run 3 variant.
  5. Run the manually built graph as variant A first: LoRA strength 0.0, no anime style prefix, Enhancer disabled. Keep every other setting unchanged.
  6. Do not add a prompt enhancer, image reference, upscaler, second pass, or extra LoRA.

4. The fixed Overdrive prompt

Every variant uses the same complete prompt for the current canonical specimen: team_tier2_a, May, based on the 1989 March CG891. The exact prompt text is shown below with the optional LoRA trigger at the beginning:

anime style, 2D hand-painted anime racing illustration, fusion of Kosuke Fujishima and Hino Matsuri visual sensibilities, expressive 1990s Japanese racing anime key art, clean cel-shaded artwork, flat opaque painted colors, delicate thin ink linework, warm golden highlights. Original Overdrive Formula 1 car for team_tier2_a, the fictional May racing team, based strictly on the 1989 March CG891 Formula 1 car and its Leyton House-era silhouette. Dominant pastel Miami Blue or Leyton Blue body color #66C5C5, restrained deep green accents #2E7D32, exposed carbon fiber and matte black only on functional wings, suspension, tires, and mechanical areas. No broad white body panels. Preserve the extremely narrow monocoque, long low nose, open cockpit, no halo, exposed wheels, visible suspension arms, sculpted sidepods, compact engine cover, period-correct front wing, and large rear wing. No words, letters, numbers, sponsor names, logos, emblems, invented lettering, driver, helmet, watermark, extra wheels, duplicated wings, cropped vehicle, PBR, normal maps, photorealism, or unrelated objects. Front three-quarter view, neutral gray background, full vehicle visible, 16:9 composition.

The Fujishima + Matsuri fusion and the CG891 palette are grounded in design/art/style-anchor-prompt.md and design/art/art-bible.md. For variant A or C, remove only the initial anime style, prefix. Krea2 has no text negative prompt; all restrictions remain in the positive prompt.

5. Run 1 — revised baseline technical reproduction

The previous Run 1 and Run 2 outputs remain historical evidence for the earlier graph. Because the graph contract and validated parameters were corrected, execute this revised graph once before using its output in Run 3.

  1. Queue the graph once.
  2. Wait for the image to save.
  3. Record the output path, dimensions, and whether the image was generated without errors.
  4. Do not judge the image as production art yet. This run proves that the graph, weights, nodes, and settings work together.

Technical pass: the graph loads every required weight, completes without a node error, saves a PNG, and repeats successfully with the same seed.

6. Run 2 — revised baseline reproducibility

  1. Queue the exact same graph again.
  2. Keep the same seed and all settings.
  3. Compare Run 1 and Run 2.

The result should be identical or visually equivalent within the normal precision of the same local pipeline. If it is not, record the difference before changing anything. A non-reproducible baseline cannot be used for controlled learning.

7. Run 3 — progressive component and trigger attribution

After the revised Run 1 and Run 2 pass, continue from the control graph in progressive order. Every run uses the same complete CG891 prompt, model, seed, resolution, sampler, steps, and CFG; change only the named variable.

Compare A→B for the trigger, A→C for the LoRA, C→D for the trigger with the LoRA active, and D→E for the Enhancer. Do not decide from one attractive image. Compare silhouette, proportion, linework, palette, unwanted realism, and structural errors.

8. Six-point visual review

CriterionPass condition
Vehicle identityImmediately reads as an original Overdrive open-wheel car.
Large-form silhouetteNose, front wing, cockpit, sidepods, rear wing, and four exposed wheels are clear.
ProportionWheels, cockpit, wings, and body mass have a believable relationship.
Style conformanceFujishima + Matsuri linework, hard cel-shaded clarity, painted textures, and warm palette are present without photorealism.
Clean surfaceNo readable text, logos, watermarks, invented branding, duplicate parts, or unrelated objects.
Reconstruction potentialThe view exposes enough stable shape information for later multi-view work.

A visually attractive image with a broken silhouette is a failure. A technically successful render with the wrong style is also a failure.

10. Advancement gate

Do not proceed to multi-view or 3D reconstruction until:

  • the manually assembled graph runs and saves successfully twice;
  • the same seed produces a reproducible result;
  • the vehicle category and large-form silhouette pass;
  • the Fujishima + Matsuri visual direction is present;
  • there is no accidental text, logo, watermark, or unrelated context;
  • the provenance record is complete;
  • one controlled A/B change has been measured.

Decision rule

assemble the graph from the node contract
  → prove the graph runs
  → prove the seed is reproducible
  → compare LoRA and enhancer one variable at a time
  → score the vehicle against the six criteria
  → record evidence
  → approve one 2D candidate
  → only then begin multi-view generation
